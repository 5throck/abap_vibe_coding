## 🧠 Critical Technical Decisions Made (and Why)

### ABAP Language / Syntax
1. **NW 7.52 `CASE` in Open SQL**: Not supported → replaced with `IF p_cancel` branching two `SELECT` statements.
2. **NW 7.52 `FIND PCRE`**: Not supported → globally replaced with `FIND REGEX`; `##REGEX_POSIX` pragma also removed.
3. **`MANDT` in JOIN ON clause**: Cannot be used — compiler manages client automatically → removed from all JOIN clauses.
4. **SELECT-OPTIONS name limit**: Max 8 characters enforced → renamed `so_carrid` → `s_carrid`.
5. **`SELECTION-SCREEN BLOCK TITLE`**: Cannot assign `TEXT-xxx` at runtime → switched to `WITH FRAME` only.
6. **TABLES declaration**: Cannot use deep (non-flat) structures → replaced with local `DATA` variables for `SELECT-OPTIONS` when using SNWD_BPA.

### Architecture
7. **OO-ABAP for `ZPROG_SBOOK_QUERY`**: `LCL_REPORT FINAL` class introduced; `RUN/FETCH_DATA/DISPLAY_ALV/SET_COL_TEXT` methods; SQL consolidated with `AND ( @p_cancel = @abap_true OR bk~cancelled = @abap_false )`.
8. **CDS over physical tables for ZSLIGHT**: Avoided data duplication — CDS views reference original SFLIGHT.
9. **EPM/SNWD_* chosen as modern demo data**: Preferred over SFLIGHT as the 7.5x-era standard.
10. **Business Object Pattern for Inventory**: Separated ZINV_STOCK (data), ZCL_INVENTORY_MANAGER (logic), ZPROG_INVENTORY_MANAGER (presentation). Alternative (direct SQL in program) was explicitly rejected.
11. **Soft delete pattern**: STATUS field ('A'=Active, 'I'=Inactive, 'D'=Deleted) — actual data preserved on deletion.
12. **UTCLONG for timestamps**: Microsecond precision in ZINV_STOCK audit trail.
13. **BAPI_GOODSMVT_CREATE for MM GR/GI**: Standard BAPI chosen for material document creation integrity.
14. **LUW management as highest risk in SD task**: `BAPI_TRANSACTION_COMMIT` handling identified as critical for Order+Delivery BAPI chain.

### Infrastructure
15. **WebSocket APC handler (ZCL_VSP_APC_HANDLER)**: AMDP and Git service instantiation commented out to allow activation on systems where those classes are absent.
16. **Dynamic Table Typing**: `TYPE ANY TABLE` added to field symbols in ZCL_VSP_RFC_SERVICE to resolve generic LOOP errors.
17. **abapGit renamed to `ZABAPGIT_STANDALONE`**: Avoids collision with standard developer version.
18. **Serial write execution enforced**: Write operations (EditSource/WriteSource) always serial, never parallelized — prevents ADT lock conflicts.

### Configuration & Tooling
19. **`vsp.exe` → `./vsp`**: Changed to platform-agnostic relative path for cross-platform portability.
20. **Features enabled progressively**: `VSP_FEATURE_TRANSPORT`, `VSP_FEATURE_RAP`, `VSP_FEATURE_UI5` added 2026-05-05.
21. **Hyperfocused mode**: Configured in `.gemini/settings.json` — routes all operations through single `sap_execute` action to reduce hallucination risk.

## 🔁 Recurring Patterns & Known Issues

### Pattern 1: ADT Lock (423) on Deploy
- **Frequency**: Occurred 3+ times across sessions
- **Trigger**: `vsp deploy` on existing objects, especially after prior failed write
- **Standard Workaround**: Always use `vsp source write` (not `vsp deploy`) for existing objects
- **Status**: Known, stable workaround exists

### Pattern 2: NW 7.52 Compatibility Patches Required
- **Frequency**: Every new SAP object with modern ABAP syntax
- **Trigger**: Any use of PCRE, `##REGEX_POSIX` pragma, or modern SQL features
- **Checklist**: Replace PCRE→REGEX, remove ##REGEX_POSIX, avoid CASE in Open SQL, avoid MANDT in JOIN ON
- **Status**: Recurring — must be checked for every new deployment

### Pattern 3: Korean/Unicode Encoding in Toolchain
- **Frequency**: Multiple occurrences in 2026-05-01
- **Trigger**: PowerShell pipe operations, WriteAllText defaults, inline Korean string literals
- **Solution**: Use `vsp source edit --old --new`, UTF-8 no-BOM encoding, English literals for screen blocks
- **Status**: Stable workarounds; Korean inline literals work when not piped

### Pattern 4: Design-Only Tasks Left Incomplete
- **Observation**: task-2026-05-05-001 (MM GR/GI) and task-2026-05-05-002 (SD Order-Delivery) reached §2 Technical Design but §3 Implementation was never filled in
- **task-2026-05-05-003** appears to be a blank template duplicate of the SD task
- **Status**: ⚠️ Two business-critical programs are DESIGNED but NOT IMPLEMENTED

### Pattern 5: TEXTPOOL Title Issues
- **Frequency**: Occurred with ZPROG_EPM_DEMO twice (original + restoration)
- **Trigger**: Creating new programs via vsp/ADT without manually setting TEXTPOOL ID 'R'
- **Solution**: Always run `INSERT TEXTPOOL` script after program creation to set title
- **Status**: Known, manual step required

## 📚 Key Lessons Learned

1. **`vsp deploy` vs `vsp source write`**: NEVER use `vsp deploy` for existing objects — always use `vsp source write`. This was learned the hard way 3+ times with 423 errors.

2. **NW 7.52 compatibility checklist is mandatory**: Before any deployment, run the mental checklist: PCRE→REGEX, remove ##REGEX_POSIX, no CASE in Open SQL, no MANDT in JOIN ON.

3. **Global config takes precedence**: The `claude_desktop_config.json` global MCP config is the actual connection source, not the project `.mcp.json`. Credentials must be set there.

4. **Korean text in toolchain requires special handling**: Never inline Korean in SELECTION-SCREEN TITLE; use INITIALIZATION for `%_x_%_app_%-text` style labels. Never pipe Korean text through PowerShell.

5. **TEXTPOOL must be set manually**: Program titles (TEXTPOOL ID 'R') are not auto-created via MCP deploy — always run INSERT TEXTPOOL script after program creation.

6. **Design tasks need a completion gate**: The project has two incomplete task handoffs (MM GR/GI, SD Order-Delivery) that never progressed past §2. The Harness workflow has a governance approval step (§1-A) that can block progress — but no mechanism currently forces completion tracking.

7. **Memory logging has gaps**: Multiple scratch `.abap` files have no corresponding memory entries. The `harness:memory-intelligence` skill was created specifically to address this, but human/agent discipline in writing memory entries remains inconsistent.

8. **Scratch directory isolation**: File isolation rule (all `.abap` in `scratch/`) appears well-enforced — no stray `.abap` files found outside scratch.

9. **Documentation drift is a real risk**: Binary names, tool counts, and URLs in setup docs became stale and required a dedicated correction pass on 2026-05-18.

10. **Parallel design, serial write**: The Harness pattern of parallelizing read-only research and serializing writes has proven correct — no lock conflicts occurred when this was followed.
