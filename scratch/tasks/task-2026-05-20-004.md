## 1. Problem Analysis

### AS-IS

Pattern C in `agents/architect.md`:
```
IF still fails: STOP and report to PM — do not proceed
```

No guidance on what to do with the N-1 objects that were already successfully modified before the failure.

### GAP

After a Pattern C abort:
- Some objects may be in an edited (inactive) state.
- Some may be already activated.
- The codebase is in a **partially refactored, inconsistent state**.
- The next session has no documented procedure for diagnosing or reversing this.

### TO-BE Requirements

Add a rollback procedure:
1. **Identify scope**: List all objects modified before the failure point.
2. **Revert unactivated objects**: Use `GetRevisionSource` to retrieve the previous version, then `WriteSource` to restore.
3. **Mark activated objects**: If already activated, document them in the task file for manual review.
4. **Create a recovery task**: PM creates a dedicated task file to track the rollback.

### Acceptance Criteria

- [ ] **AC-01**: `agents/architect.md` Pattern C template includes a ROLLBACK block after the "STOP and report to PM" instruction.
- [ ] **AC-02**: The rollback procedure references `GetRevisionSource` for retrieving pre-edit snapshots.
- [ ] **AC-03**: `docs/task-template.md` §2 (Technical Design) includes a Rollback Plan field.
- [ ] **AC-04**: `docs/context.md` ABAP Development Rules section notes that Pattern C failures require rollback execution before starting a new task.

### Rollback Block to Add (Pattern C)

```
  IF SyntaxCheck fails twice on object N:
    STOP — do not proceed to object N+1
    ROLLBACK PROCEDURE:
      1. List all objects modified in steps 1..(N-1)
      2. For each unactivated object: GetRevisionSource → WriteSource (restore previous version)
      3. For each activated object: document in task §2 Rollback Plan as "manual review required"
      4. PM creates recovery task: task-YYYY-MM-DD-NNN-rollback.md
      5. Report to user: [modified objects list] + [rollback status per object]
```
