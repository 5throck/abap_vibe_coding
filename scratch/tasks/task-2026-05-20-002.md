## 1. Problem Analysis

### AS-IS

`agents/interface-expert.md` declares the following tools:
- `GetODataMetadata`
- `TestODataService`
- `GetCDSExposure`
- `GetCDSDependencies`
- `GetSource`
- `SearchObject`

The current `.mcp.json` runs vsp in `--mode hyperfocused`, which per `docs/context.md` exposes a single unified `SAP` tool rather than individual named tools.

### GAP

It is unverified whether the above tools are accessible as sub-operations of the unified `SAP` tool or as separate MCP tool registrations in hyperfocused mode.

If they are NOT available, dispatching `interface-expert` will silently fail on every OData/RFC analysis task.

### TO-BE Requirements

1. Run `vsp --mode hyperfocused` and call `GetFeatures` or equivalent to enumerate available tools.
2. Cross-reference the list against `agents/interface-expert.md` tool declarations.
3. Update the agent definition: keep confirmed tools, annotate or remove unavailable ones.
4. If critical tools (GetODataMetadata, TestODataService) are unavailable, evaluate switching to `--mode focused` for Interface Expert tasks, OR document a manual fallback procedure.

### Acceptance Criteria

- [ ] **AC-01**: A confirmed list of tools available in `hyperfocused` mode is documented in `docs/context.md` or a new `docs/mcp-mode-tools.md`.
- [ ] **AC-02**: `agents/interface-expert.md` only lists tools confirmed as available in the active MCP mode.
- [ ] **AC-03**: If any critical tool is unavailable, a fallback procedure or mode-switch recommendation is documented.
- [ ] **AC-04**: `vsp-audit.ps1` / `vsp-audit.sh` includes a new Check 6 that validates MCP mode tool availability at session start.
