## 1. Problem Analysis

### AS-IS

`agents/test-runner.md` Quality Gate Standards:
```
- ATC P1: Zero tolerance (blocks activation/transport).
- ATC P2: PM/User review required.
- ATC P3: Log only.
```

The P2 path ends at "review required" with no defined:
- Decision criteria (what justifies allow vs. fix?)
- Recording location (Task file? Memory log? Inline comment?)
- Disposition options (suppress, fix, escalate to user)
- Timeout or SLA (how long can a P2 stay unresolved?)

### GAP

When the test-runner reports P2 findings, the PM has no framework to make a consistent decision. Different sessions may handle the same P2 finding differently, leading to inconsistency across the codebase.

### TO-BE Requirements

Define a 3-option P2 disposition framework:
1. **Fix** — P2 is a real code quality issue; code-writer must resolve before transport.
2. **Suppress with justification** — P2 is a known false positive or acceptable deviation; PM documents reason in Task §4.2.
3. **Defer** — P2 is valid but low-impact; logged as backlog item in `memory/` and deferred to next cycle.

### Acceptance Criteria

- [ ] **AC-01**: `docs/testing-guidelines.md` contains a dedicated "ATC P2 Escalation" section with the 3-option framework.
- [ ] **AC-02**: `agents/test-runner.md` Quality Gate Standards updated to reference the escalation workflow.
- [ ] **AC-03**: Task template (`docs/task-template.md`) §4.2 updated with P2 disposition field.
- [ ] **AC-04**: `AGENTS.md` §5 Finalization step includes P2 disposition confirmation as a gate condition.
