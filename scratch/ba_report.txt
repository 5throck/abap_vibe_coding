## 4. GAP Analysis

### 🔴 Critical Gaps (Unaddressed Business Requirements)

| # | Gap | Business Impact | Severity |
|---|-----|----------------|----------|
| G-01 | **ZINV_STOCK is isolated from SAP Material Master (MARA/MARC/MARD/MBEW)** | No material validation against SAP master data; material_id is free-text char(20), not MATNR | HIGH |
| G-02 | **No goods movement integration (MIGO/movement types)** | Stock changes are not posted as material documents (MKPF/MSEG) — inventory is off the SAP books | HIGH |
| G-03 | **No FI posting on stock changes** | Add/Withdraw stock generates no accounting entries — financial statements are not affected | HIGH |
| G-04 | **No purchase order linkage** | Goods receipts cannot be linked to purchase orders (EKKO/EKPO) | HIGH |
| G-05 | **No SD order-to-cash process** | `ZPROG_EPM_DEMO` uses demo tables — real customer order, delivery, and billing are absent | HIGH |
| G-06 | **No CO object assignment (cost center / internal order)** | Inventory movements generate no CO actual costs | MEDIUM |
| G-07 | **No unit of measure conversion** | `add_stock`/`withdraw_stock` accepts UoM parameter but performs no ISO conversion | MEDIUM |
| G-08 | **No batch / serial number tracking** | ZINV_STOCK has no batch or serial number fields (no CHARG equivalent) | MEDIUM |
| G-09 | **No multi-client / transport-ready packaging** | All objects in `$TMP` (local package) — not transportable to QA/Production | MEDIUM |
| G-10 | **No valuation / costing** | No price/value fields in ZINV_STOCK — no moving average or standard cost link | LOW |
| G-11 | **No stock reservation or blocked stock** | Only LABST (unrestricted) equivalent is modeled — no EINME or SPEME equivalent | LOW |

## 5. Module-by-Module Recommendations

### 📦 MM — Materials Management
**Current State**: Custom inventory manager exists but is entirely disconnected from SAP MM.
- **Recommendation 1**: Replace free-text `material_id` with proper `MATNR` typed field; add validation against `MARA`/`MARC`.
- **Recommendation 2**: Replace direct `ZINV_STOCK` updates with `BAPI_GOODSMVT_CREATE` calls using movement types (101 for receipt, 201/261 for issue) so proper MKPF/MSEG material documents are created.
- **Recommendation 3**: Add purchase order reference fields (`EBELN`/`EBELP`) to support GR-based IV workflows.
- **Recommendation 4**: Add batch (`CHARG`) and valuation type (`BWTAR`) fields for split-valuation scenarios.
- **Priority**: HIGH — core data integrity concern.

### 🚀 SD — Sales & Distribution
**Current State**: Only an EPM demo screen exists; no real SD objects.
- **Recommendation 1**: Implement a basic sales order inquiry program reading `VBAK`/`VBAP` with LFSTA/FKSTA delivery and billing status filters (follow the common query patterns in `sd-analyst.md`).
- **Recommendation 2**: Build a delivery monitor against `LIKP`/`LIPS` with `WBSTK <> 'C'` filter.
- **Recommendation 3**: Retire `ZPROG_EPM_DEMO` as a placeholder; replace with real SD reporting or mark explicitly as "training demo."
- **Priority**: HIGH if SD business processes are in scope; MEDIUM if this remains a training project.

### 💰 FI — Financial Accounting
**Current State**: Zero implementation. The `fi-analyst.md` context file is present but unused.
- **Recommendation 1**: Add a basic open-item report using `BSID` (open customer items) and `BSIK` (open vendor items) views — avoid direct `BSEG` joins for performance.
- **Recommendation 2**: When MM stock movements are implemented (see MM above), ensure FI automatic postings via T030/OBYC account determination are verified.
- **Recommendation 3**: Consider `ACDOCA`-based universal journal query for S/4HANA environments.
- **Priority**: MEDIUM — no FI posting means the inventory system has no financial impact.

### 📊 CO — Controlling
**Current State**: Zero implementation.
- **Recommendation 1**: Add cost center (`KOSTL`) assignment to the `ZINV_STOCK` table or the goods movement calls, so material consumption posts to CO cost objects.
- **Recommendation 2**: If internal order tracking is required, add `AUFNR` linkage to goods issues (movement type 261).
- **Priority**: LOW until MM and FI foundations are in place.

### 🚛 LE — Logistics Execution
**Current State**: Zero implementation.
- **Recommendation 1**: If the `task-2026-05-05-003.md` request ("online order entry and goods issue program") proceeds to implementation, LE should provide delivery (LIKP/LIPS) and PGI logic using `BAPI_OUTB_DELIVERY_CREATE_SLS`.
- **Recommendation 2**: At minimum, implement a delivery status monitor (LIKP.WBSTK filter) as a lightweight read-only LE touchpoint.
- **Priority**: MEDIUM — required to complete the SD order-to-cash flow.

### 🏭 PP — Production Planning
**Current State**: Zero implementation. No production order, BOM, or MRP objects exist.
- **Recommendation 1**: Unless manufacturing is explicitly in scope, defer PP implementation until SD/MM/FI are established.
- **Recommendation 2**: If goods issues from production are needed, add movement type 261 support in the MM layer (`BAPI_GOODSMVT_CREATE`).
- **Priority**: LOW — no evidence of manufacturing business requirements in existing code or tasks.

## 6. Open Business Risks

| # | Risk | Probability | Impact | Mitigation |
|---|------|:-----------:|:------:|------------|
| R-01 | **Data integrity** — `ZINV_STOCK` stocks diverge from real SAP `MARD` stocks | High | High | Mandatory: migrate to `BAPI_GOODSMVT_CREATE` + `MARD` as source of truth |
| R-02 | **No audit trail** — stock changes have change timestamps but no material document number linking to MKPF/MSEG | High | High | Integrate movement type posting; store `MBLNR`/`MJAHR` in ZINV_STOCK |
| R-03 | **Non-transportable objects** — all in `$TMP` package | High | Medium | Move to named Z-package before any productive use |
| R-04 | **Financial exposure** — inventory adds/reductions create no FI/CO postings | Medium | High | Implement `BAPI_GOODSMVT_CREATE` with automatic FI integration |
| R-05 | **No authorization check** — `ZCL_INVENTORY_MANAGER` has no `AUTHORITY-CHECK` for plant/storage location | High | Medium | Add `AUTHORITY-CHECK OBJECT 'M_MSEG_BWA'` for movement type and plant |
| R-06 | **No unit-of-measure validation** — `add_stock`/`withdraw_stock` mix units silently | Medium | Medium | Validate UoM consistency or perform ISO conversion before quantity arithmetic |
| R-07 | **Demo artifacts in codebase** — `ZPROG_EPM_DEMO`, `ZPROG_SFLIGHT_ALV`, `ZSLIGHT` CDS views are training objects | Low | Low | Separate training objects into a dedicated package; document as non-productive |
| R-08 | **No negative stock prevention** — code checks `quantity < iv_quantity` but no link to SAP standard negative-stock settings (MARC.LGPRO) | Low | Low | Add plant-level negative stock setting validation |
