## ABAP Inventory Management System (New Development)

### 1. ZINV_STOCK (Database Table)
- **Type**: Table (DDL source)
- **Package**: $TMP
- **Location**: scratch/zinv_stock.tabl
- **Purpose**: Master table for inventory management

**Technical Decisions**:
- Used CDS table definition (modern approach) instead of SE11
- Soft delete pattern with STATUS field ('A'=Active, 'I'=Inactive, 'D'=Deleted)
- Audit trail fields: CREATED_BY, CREATED_AT, CHANGED_BY, CHANGED_AT
- UTCLONG for timestamp (microsecond precision)
- MIN_STOCK and MAX_STOCK for inventory monitoring

**Key Fields**:
- Primary Key: MATERIAL_ID (char20), PLANT (char10), STORAGE_LOC (char10)
- Business Data: QUANTITY (quan13,3), UNIT (unit3), CATEGORY (char10)
- Control: MIN_STOCK, MAX_STOCK, STATUS

### 2. ZCL_INVENTORY_MANAGER (Business Logic Class)
- **Type**: Class
- **Package**: $TMP
- **Location**: scratch/zcl_inventory_manager.clas.abap
- **Purpose**: Encapsulate inventory management business logic

**Technical Decisions**:
- OOP design with constructor-based initialization
- Exception handling with CX_ABAP_INVALID_VALUE
- Validation methods for quantity and status
- Static factory method CREATE_NEW_ITEM
- Return abap_bool for success/failure indication

**Public Methods**:
- ADD_STOCK(): Add quantity with audit trail
- WITHDRAW_STOCK(): Reduce quantity with availability check
- GET_CURRENT_STOCK(): Return inventory structure
- CHECK_STOCK_AVAILABILITY(): Check if quantity available
- SET_MIN_MAX_STOCK(): Update min/max levels
- UPDATE_DESCRIPTION(): Update material description
- DELETE(): Soft delete (status='D')
- GET_ALL_INVENTORY(): Return all active items
- GET_LOW_STOCK_ITEMS(): Return items below minimum
- CREATE_NEW_ITEM(): Static method for new item creation

### 3. ZPROG_INVENTORY_MANAGER (Main Program)
- **Type**: Executable Program (Report)
- **Package**: $TMP
- **Location**: scratch/zprog_inventory_manager.prog.abap
- **Purpose**: User interface for inventory operations

**Technical Decisions**:
- SELECTION-SCREEN blocks for organized input
- Dynamic screen modification (MODIFY_SCREEN)
- Centralized validation in AT SELECTION-SCREEN
- Modular FORM routines for each operation
- Constants for action codes
- Color-coded list output

**Actions**:
- C (Create), D (Display), A (Add), R (Reduce)
- M (Modify), X (Delete), L (List), S (Low Stock)
- E (Exit)

### 4. ZINV (Message Class)
- **Type**: Message Class
- **Package**: $TMP
- **Location**: scratch/zinv_messages.tmsg.abap
- **Purpose**: Centralized message management

**Message Organization**:
- Errors: 001-099 (Duplicate, Not Found, Insufficient Stock)
- Success: 005-016 (Created, Added, Reduced, Modified, Deleted)
- Warning: 050-059 (Below Min, Above Max)
- Info: 100-103 (Displaying, Processing)

### Design Pattern Applied
**Business Object Pattern**: Separated data (ZINV_STOCK), logic (ZCL_INVENTORY_MANAGER), presentation (ZPROG_INVENTORY_MANAGER)
- **Benefits**: Reusable logic, easier testing, clear separation of concerns
- **Alternative Rejected**: Direct SQL in program (harder to maintain, no reuse)
